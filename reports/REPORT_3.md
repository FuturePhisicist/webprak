# Третий отчет

## Реализованный Web-интерфейс

Для Web-интерфейса добавлены контроллеры Spring MVC и HTML-шаблоны Thymeleaf. JSP-страницы не используются.

* главная страница с переходами к служащим, подразделениям, должностям и графу подразделений;
* список служащих с поиском по ФИО, фильтрами по подразделению и должности, сортировкой;
* карточка служащего с текущим назначением, стажем, статусом и переходом к истории;
* форма добавления и редактирования служащего;
* форма назначения служащего на должность и перевода на новую должность;
* история назначений служащего;
* список подразделений с руководителем, головным подразделением, количеством внутренних подразделений и активных сотрудников;
* карточка подразделения с внутренними подразделениями, активными сотрудниками и должностями в подразделении;
* форма добавления и редактирования подразделения;
* добавление должности в подразделение через таблицу `department_positions` с указанием количества ставок;
* удаление должности из подразделения с проверкой отсутствия активных назначений;
* граф подразделений с корректным обходом дерева: родитель выводится перед своими дочерними узлами;
* список должностей с кратким описанием, количеством использующих подразделений и активных назначений;
* карточка должности со списком подразделений, количеством ставок, занятыми и свободными ставками;
* форма добавления и редактирования должности;
* единая страница ошибки 404 для отсутствующих сущностей.

## Классы контроллеров

* `HomeController` --- главная страница.
* `EmployeeController` --- список, карточка, создание, редактирование, удаление, история и назначение служащих.
* `DepartmentController` --- список, карточка, создание, редактирование, удаление, граф подразделений, управление должностями подразделения.
* `PositionController` --- список, карточка, создание, редактирование и удаление должностей.
* `WebExceptionHandler` --- обработка `EntityNotFoundException` и вывод страницы 404.

## Работа с базой данных

Слой доступа к данным реализован через Spring Data JPA:

* сущности: `Employee`, `Department`, `Position`, `DepartmentPosition`, `Assignment`;
* репозитории: `EmployeeRepository`, `DepartmentRepository`, `PositionRepository`, `DepartmentPositionRepository`, `AssignmentRepository`;
* сервисы: `EmployeeService`, `DepartmentService`, `PositionService`, `AssignmentService`.

Для страниц, которым нужны связанные данные при `spring.jpa.open-in-view=false`, добавлены отдельные repository-методы с `join fetch`. Обычные сервисные методы сохранены отдельно, чтобы не ломать существующие сервисные сценарии.

SQL-скрипты:

* `sql/01_create_db.sql` --- создание схемы и таблиц;
* `sql/02_init_db.sql` --- тестовые данные и настройка sequence после ручных ID;
* `sql/03_dump_db.sql` --- дамп основных таблиц.

## Конфигурация и сборка

Используется Spring Boot, основной класс приложения:

* `ru.msu.cmc.webprak.WebprakApplication` с аннотацией `@SpringBootApplication`.

Конфигурация приложения:

* `src/main/resources/application.properties`.

В `build.gradle` настроены:

* сборка проекта;
* запуск приложения через `bootRun`;
* запуск тестов;
* отчет покрытия JaCoCo;
* задачи `dbCreate`, `dbInit`, `dbClean`, `dbDump`;
* служебные задачи `testVerbose`, `testSummary`, `coverage`.

Для JaCoCo из отчета исключен только bootstrap-класс `WebprakApplication.class`, потому что покрытие `main()` потребовало бы запускать приложение из теста.

## Сценарии системного тестирования

1. Главная страница открывается и содержит переходы ко всем ключевым разделам.
2. Поиск служащего по существующему ФИО возвращает найденную запись.
3. Поиск служащего по отсутствующему ФИО возвращает сообщение об отсутствии данных.
4. Фильтры служащих по подразделению и должности возвращают нужные записи.
5. Сортировки служащих по ФИО, дате приема, подразделению и должности выполняются без ошибок.
6. Запрос карточки отсутствующего служащего возвращает страницу ошибки 404 с конкретным сообщением.
7. Добавление служащего с корректными данными завершается редиректом на карточку новой записи.
8. Добавление служащего с ошибкой валидации возвращает форму и сообщение конкретного типа.
9. Редактирование служащего с корректными данными сохраняет запись.
10. Редактирование служащего с ошибкой валидации возвращает форму и сообщение.
11. Удаление служащего без активного назначения завершается успешно.
12. Удаление служащего с активным назначением возвращает бизнес-ошибку.
13. Назначение служащего без активного назначения создает новое назначение.
14. Перевод служащего с активным назначением закрывает старое назначение и создает новое.
15. Назначение на занятую ставку возвращает бизнес-ошибку о нехватке свободных ставок.
16. Карточка подразделения открывается и показывает руководителя, головное подразделение, внутренние подразделения, должности и сотрудников.
17. Создание, редактирование и удаление подразделения выполняются через Web-интерфейс.
18. Ошибки создания, редактирования и удаления подразделения возвращают отдельные сообщения.
19. Добавление должности в подразделение создает запись `department_positions`.
20. Повторное добавление той же должности в подразделение возвращает бизнес-ошибку.
21. Удаление должности из подразделения выполняется только если нет активных назначений.
22. Граф подразделений возвращает узлы в корректном древовидном порядке.
23. Карточка должности показывает подразделения, общее количество ставок, занятые и свободные ставки.
24. Создание, редактирование и удаление должности выполняются через Web-интерфейс.
25. Ошибки создания, редактирования и удаления должности возвращают отдельные сообщения.
26. Form-классы и вспомогательные методы моделей покрыты unit-тестами.

Системные тесты реализованы на Spring Boot Test + MockMvc:

* `src/test/java/ru/msu/cmc/webprak/controller/WebSystemTest.java`.

Дополнительные unit-тесты для покрытия сервисов, form-классов и моделей:

* `src/test/java/ru/msu/cmc/webprak/service/*Test.java`;
* `src/test/java/ru/msu/cmc/webprak/MiscCoverageTest.java`.

## Запуск

```bash
./gradlew clean test
./gradlew clean test jacocoTestReport
```

Для просмотра приложения в браузере при запуске через Docker:

```bash
sudo docker compose up -d --build
sudo docker exec -it devshell_container bash
./gradlew dbInit
./gradlew bootRun
```

После запуска приложение доступно с хоста:

```text
http://localhost:8080/
```

Основные страницы:

```text
http://localhost:8080/employees
http://localhost:8080/departments
http://localhost:8080/departments/graph
http://localhost:8080/positions
```
